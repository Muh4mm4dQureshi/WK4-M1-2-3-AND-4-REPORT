# Penetration Testing Report: Mediroza General Hospital

## 01 Executive Summary

A structured manual security assessment was conducted against `https://medirozahospital.com` and `www.medirozahospital.com` (`199.188.201.16:443`) running **Mediroza CMS 1.4.2** on **PHP/8.2.36** and **LiteSpeed** with a **MySQL/MariaDB** backend. The assessment identified critical authentication, file-protection, and data-exposure weaknesses across Milestones 1 through 3:

- **Authentication Bypass via SQL Injection:** Unsanitized input in the `username` parameter of `/patient/login.php` allowed SQL syntax manipulation (`admin' #`) to bypass login verification and access the patient portal (`My Reports`).
- **Weakly Protected Patient Lab Reports:** Three encrypted PDF pathology reports (`LR-2024-1187`, `LR-2024-1192`, and `LR-2024-1205`) were accessible from the portal and had their passwords recovered using the Networkwalks password hash cracker.
- **Exposed Database Backup (`mediroza_db_backup_2019.sql`):** An unauthenticated SQL backup dump (`mediroza_hr`) exposed confidential records for 30 hospital staff members (including `monthly_salary_zar`, `national_id`, email, and phone details) and 10 shareholders (including ownership percentages, share counts, and share classes).

## 02 Scope and Methodology

- **Target Scope:** `https://medirozahospital.com` and `www.medirozahospital.com` (`199.188.201.16:443`).
- **Identified Stack:** Mediroza CMS 1.4.2, PHP/8.2.36, LiteSpeed web server, MySQL/MariaDB.
- **Tools & Techniques:** Browser Developer Tools (Network, Request, Cookies, Response inspection), manual `curl` requests, SQL injection comment testing, Networkwalks password hash cracker for PDF password recovery, and manual inspection of exposed files and SQL backup contents.
- **Testing Approach & Limitations:** Testing was performed manually with controlled single requests within the authorized target scope without automated flooding or denial-of-service activity.

## 03 Findings and Proof of Exploitation

### Finding 1: SQL Injection and Authentication Bypass in `/patient/login.php` (Milestone 1)

**Description:** Submitting a single quote (`'`) in `username` on `/patient/login.php` returned HTTP `200` with a MySQL syntax error inside `<div class="alert">`: `Warning: mysqli_query(): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near '&#039;' at line 1`. Testing `admin` with an empty password returned `Incorrect password`, confirming the account existed.

**Proof of Exploitation:** Sending `username=admin' #` in a `POST` request to `/patient/login.php` bypassed authentication and rendered `My Reports | Mediroza Patient Portal` under an active session (`PHPSESSID=sp1ahrsm1sj3uaisnpt345t75s`), exposing three encrypted lab reports:

- `Pathology Report - S. Dlamini` (`Lab Ref LR-2024-1187`, `2024-11-04`, `download.php?id=1`)
- `Pathology Report - P. Reddy` (`Lab Ref LR-2024-1192`, `2024-11-05`, `download.php?id=2`)
- `Pathology Report - E. Thompson` (`Lab Ref LR-2024-1205`, `2024-11-06`, `download.php?id=3`)

### Finding 2: Recovery of Passwords for Encrypted Patient PDF Reports (Milestone 2)

**Description:** The three pathology PDFs downloaded from `download.php?id=1`, `download.php?id=2`, and `download.php?id=3` were encrypted.

**Proof of Exploitation:** Using the Networkwalks password hash cracker, the passwords for all three encrypted PDF lab reports were recovered, allowing access to the report contents for inspection.

### Finding 3: Unauthenticated Exposure of Confidential HR and Shareholder Database Dump (Milestone 3)

**Description:** The plain-text backup file `mediroza_db_backup_2019.sql` (generated by Mediroza CMS 1.4.2 for database `mediroza_hr`, dated `2019-08-27 02:14:03`) was accessible, containing full table definitions and `INSERT` statements for `staff` and `shareholders`.

**Proof of Exploitation:** Inspection of `mediroza_db_backup_2019.sql` revealed:

- **`staff` Table (30 records):** Includes `id`, `full_name`, `job_title`, `department`, `email`, `phone`, `national_id`, `monthly_salary_zar`, and `date_joined` (for example, `Dr. Johan van der Merwe` at `160000` ZAR/month, `Sarah Botha` at `152000` ZAR/month, `Dr. Rajesh Naidoo` at `138000` ZAR/month, down to `Linda Fourie` at `19000` ZAR/month).
- **`shareholders` Table (10 records):** Includes `id`, `shareholder_name`, `share_percent`, `shares_held`, and `share_class` (`Ordinary` and `Preferential`), led by `Dr. Rajesh Naidoo` (`18.0%`, `180000` shares), `Cedar Health Holdings (Pty) Ltd` (`15.0%`, `150000` shares), `Dr. Johan van der Merwe` (`12.0%`, `120000` shares), and `Reddy Family Trust` (`11.0%`, `110000` shares).

## 04 Risk Rating

| Finding | Severity | Justification |
| :--- | :--- | :--- |
| **Exposed `mediroza_db_backup_2019.sql` (`staff` salaries, IDs, and `shareholders`)** | **Critical** | Directly exposes sensitive employee compensation, national IDs, contact details, and corporate ownership data in plain text without requiring authentication. |
| **SQL Injection Authentication Bypass in `/patient/login.php`** | **Critical** | Allows unauthenticated attackers to bypass login controls via SQL comment injection (`admin' #`) and gain access to restricted patient portal resources. |
| **Weakly Protected Encrypted Patient Lab Reports** | **High** | Encrypted lab report passwords were cracked using the Networkwalks password hash cracker, exposing sensitive medical/pathology records once retrieved. |

## 05 Recommendations and Remediation

- **Use Parameterized Queries / Prepared Statements:** Replace direct string concatenation in `mysqli_query()` on `/patient/login.php` (and across the application) with parameterized prepared statements (`mysqli_prepare` / `bind_param` or PDO), and suppress verbose database error output in production (`display_errors = Off`).
- **Remove Publicly Accessible Backups and Enforce Access Controls:** Immediately remove `mediroza_db_backup_2019.sql` and any other backup archives from web-accessible directories, store backups outside the document root or in restricted storage, and require strict authentication and authorization checks on all endpoints.
- **Strengthen Document Encryption and Access Controls:** Use strong encryption and strong, unique passwords for sensitive PDF documents, avoid relying solely on password-protected files as a substitute for proper authorization controls on `download.php`, and rotate any exposed credentials or sensitive identifiers as appropriate.
